# Editor content pitfalls — symptom → cause → fix (UE 5.8)

Engine facts that each cost a repeat in earlier projects, for anyone changing content through editor python
(`ue.py` over Python Remote Execution, `-run=pythonscript`) or Epic's toolsets. Python mines
(`save_asset(only_if_is_dirty)`, `.umap` via `load_asset`, loading during PIE, globals between calls) are in
`references/python-in-editor.md` and not repeated here. Search this file by symptom words (`rg -n -i "grey|checker" <skill>/references/content-pitfalls.md`); do not read it whole.

The common thread: **the editor lies in your favour.** It fixes things at load, keeps unsaved edits in memory,
and draws the last good shader. The truth is in the file on disk, a cold editor start, the log, or a packaged
build. Verify there.

Sections: Saving · Packages and references · Blueprint graphs · Python in the editor and in PIE · Materials ·
Meshes and skeletal · Animation · Niagara · Levels and actors · UMG, Slate, CommonUI · Audio · Naming (recommended).

## Saving — the edit that lives only in memory

- **A texture property changed, nothing happens, nothing saves.** `ObjectTools.set_properties` on a `Texture2D` changes the property in memory only: the texture is neither rebuilt nor marked dirty, so renders keep the old mips and `save_assets` writes nothing. **Fix:** change it where the editor rebuilds and dirties it — the Texture Editor, or python `tex.modify()`, `tex.set_editor_property(...)`, `tex.post_edit_change()` and a save (this python form is the usual editor path, not measured here); confirm with the file's mtime / `git status`.
- **`StringTableTools.set_entry` works, `get_entry` reads it, `save_assets` returns true — the `.uasset` is unchanged.** `set_entry` does not dirty the package, so there is nothing to save (`is_dirty` is false right after). **Fix:** dirty it separately (e.g. `AssetTools.update_metadata_tags`) then save; confirm with `git status`.
- **A python script moved / turned / scaled actors, `save_current_level` returned without error, the map on disk is unchanged.** Move-only edits leave the level package clean. **Fix:** `actor.modify()` BEFORE the change, then `unreal.EditorLoadingAndSavingUtils.save_map(world, path)`; check by loading the map afresh, never from the same session's memory.
- **A Blueprint reparent / new event / new node is gone after the editor stops.** `set_parent`, `add_event`, `create_node` change the in-memory Blueprint only. **Fix:** `AssetTools.save_assets([path])` in the same session, before any build stops the editor.
- **An imported mesh vanished after a restart.** `StaticMeshTools.import_file` / `SkeletalMeshTools.import_file` do not save the package. A skeletal import creates three packages — `SK_X`, `SK_X_Skeleton`, `SK_X_PhysicsAsset` — save all of them (`find_assets(<folder>)`). **Fix:** save right after the import.
- **The editor crashes during a batch of animation imports.** Two unsaved animation imports in one session crash it. **Fix:** import one file, save, then the next.
- **Bones merged into a shared skeleton on import (or a root bone renamed) are gone or wrong on the next boot.** The skeleton change exists only in memory until something saves the `USkeleton`. **Fix:** save the skeleton explicitly; read the bone list back from a second mesh on the same skeleton.
- **`save_assets` returned true during PIE and wrote nothing.** Saving is a no-op while PIE runs. **Fix:** stop PIE first (`EditorAppToolset.StopPIE` / `editor_request_end_play`).
- **An edit made by hand in the GUI editor «does not keep» — the file on disk is older than the edit.** The GUI log has `MoveFile was unable to move '<asset>.uasset' ... (Error Code 32)`: a second (headless) editor holds the same package loaded, Windows refuses to replace the file. Any agent read of the asset loads it. **Fix:** stop the headless editor, then save again in the GUI. When someone says an edit "does not keep", grep their log for `Error Code 32` first.
- **An asset the check only meant to change for one run is modified on disk (`git status` shows it).** A value set for the check stayed in a package, and something saved it later: the script itself, `save_assets([])` (saves every dirty package), a person, or the editor on close. Python over Remote Execution and toolset calls save nothing by themselves. **Fix:** put one-run state into the PIE world (attributes, spawned actors), not into assets; before leaving, list your dirty packages (`EditorLoadingAndSavingUtils.get_dirty_content_packages()` / `get_dirty_map_packages()`) and revert what was only for the check; after every check run `git status` over `Content/` and restore files nobody meant to change with `git checkout -- <file>` while the editor is closed; send python into an editor this session did not start only with the person's OK (`ue.py --allow-foreign`).
- **Triggers and modifiers added to an Input Mapping Context from python are `None` after a restart.** `unreal.InputTriggerPulse()`, `unreal.InputModifierDeadZone()` and other instanced objects created in python have no asset outer and are not serialized; `save_asset` returns true and the same session reads them back fine. An action left without its trigger fires every frame. **Fix:** change fields of existing instanced objects only; create new ones by hand in the editor or in C++. Re-check every asset edit after an editor restart, not in the session that made it.
- **`fill_data_table_from_json_string` hangs the call and the log stops.** Rows that omit fields log `LogCSVImportFactory: Imported DataTable '...' - N Problems` and open a modal window titled `Message`; the import itself is applied. **Fix:** build every new row from a full exported row (`export_data_table_to_json_string`) including every nested struct field; if the window is up, find the visible `UnrealEditor` window titled `Message` and close it with `PostMessage(hwnd, WM_CLOSE)`, then `save_asset(path, False)`.

## Packages and references

- **Moved a StringTable; every text that used it is corrupt after a resave.** Its referencers are re-saved with a table id missing from their name map (ensure «Name … is not mapped when saving»). **Fix:** before the move add `[Core.StringTable] +StringTableRedirects=(OldStringTable=…,NewStringTable=…)` to `DefaultEngine.ini` and restart the editor; move; drop the section after.
- **`StringTableTools.import_file` onto an existing name answered «already exists / Failed to import» — and the `.uasset` is gone.** **Fix:** import only new names; extend an existing table with `set_entry` + forced dirtying; after any refused import check `git status` and `git checkout -- <path>`.
- **After a folder move everything loads — until the redirect is pruned; then packs lose internals or a Packed Level Actor opens the wrong world.** A soft object path is a string in a property; reference fix-up walks dependency edges only, and a resave writes the same string back. **Fix:** with the redirect still in place, in one editor: `unreal.AssetToolsHelpers.get_asset_tools().rename_referencing_soft_object_paths(packages, {old: new})`, then `EditorAssetLibrary.save_directory(root, only_if_is_dirty=False, recursive=True)`, drop the redirect last; prove on a cold boot without it. Or a prefix `+PackageRedirects` in `[CoreRedirects]`.
- **A soft reference set through a property string is null in game, and every read-back «passes».** A soft reference resolves only from the OBJECT path (`/Game/D/SM_X.SM_X`); a package path makes `LoadSynchronous()` return null, and string comparisons do not resolve it. **Fix:** always write `Package.Object`; when a check passes and the feature is absent, look for the consumer's «did not resolve» log line.
- **A move / delete returns false, or «held by a loaded settings/CDO».** The asset is pinned by a loaded config default, CDO or the current world. **Fix:** repoint the `Config/*.ini` (or the default object) to the new path, restart, then move; for the current map, load another one first.
- **A dangling reference disappeared entirely after a routine pass; nothing tells what it pointed at.** An unresolvable import becomes null on load and the next save writes the null — one load + one save, no warning. **Fix:** freeze assets with dangling references (no move, fixup or analysis pass that opens them); restore every target at the path the references name first. Reading the dangling paths from the `.uasset` bytes (plain strings in the import table) is safe. After a save only git brings it back.
- **«Who references X» answers nothing for an asset that is clearly used.** (a) The asset registry does not see references from C++ (`"/Game/..."` strings, `ConstructorHelpers`): `rg` `Source/` and `Plugins/*/Source` too. (b) A package saved a moment ago has no dependencies as far as the registry is concerned — `AssetCreated` does not read the saved file's dependency table. **Fix (b):** `IAssetRegistry::ScanFilesSynchronous({Filename}, /*bForceRescan*/ true)` after saving a package you will ask reference questions about.
- **An unreferenced-asset report reads like a delete list.** It is not one. Reachability from the maps and primary assets misses what (a) above misses, plus assets loaded by name at runtime, kept for a coming feature or used only by a person in the editor. Such a report is a size and debug read; whether an asset is needed is a person's call — hand them the list, do not delete from it. When a check looks for an asset's name in text (sources, comments, docs), a hit on its folder vouches for nothing under it: only the asset's own path counts as a mention.
- **Delete reported success, the file is still on disk** (registry later: «marked as deleted in editor, but has been modified on disk»). Worlds and any live-held package (a skeletal mesh just created, `Waiting for skinned assets to be ready`) are not deleted; a Blueprint loaded for the delete leaves compile leftovers that reference its class until the next GC, `ObjectTools::CleanupAfterSuccessfulDelete` counts them as referencers and silently drops the file. **Fix:** always check the file afterwards; for a `.umap` load another map, delete, remove the file, rescan; for a Blueprint load + `CollectGarbage(GARBAGE_COLLECTION_KEEPFLAGS)` before the delete — or stop the editor and delete on disk.
- **Relocating an asset a `.umap` references hangs the headless editor** (idle CPU, log stops mid-move, the port stops answering). `IAssetTools::FixupReferencers` re-saves the referencing world packages, a headless world fails to save and opens the modal `SFixupRedirectorsReport`, which waits for a click forever. **Fix:** never let a headless editor run redirector fix-up over maps; rewire referencers yourself through `UEditorLoadingAndSavingUtils::SavePackages`, or do that move in the GUI.
- **A case-only folder rename (`KEYS/` → `Keys/`) changes the file names and leaves the folder.** Windows resolves `Keys/` to the surviving `KEYS` dir; the registry compares case-insensitively; `core.ignorecase=true` hides it from git. **Fix:** rename through an intermediate name on disk AND in the registry, then `git rm -r --cached <OLD>` + `git add <NEW>`.
- **A copied texture still depends on the pack it came from.** `UTexture::CompositeTexture` (e.g. `CTM_NormalRoughnessToGreen`) is a compression-time input, not a slot; copy tools do not rewire it, and it breaks when the source pack is deleted. **Fix:** before deleting a pack, walk `get_dependencies` of the copies; repoint or clear `CompositeTexture`, save.
- **A copied/relocated Niagara system depends on the original Parameter Collection again after a restart.** The collection path is baked as a string into compiled VM data (`FNiagaraVMExecutableData::ParameterCollectionPaths`, `NiagaraScript.h:506`) and re-resolved on every load; no object-graph rewrite or plain resave changes it. **Fix:** move the `NPC_` keeping its redirector, recompile and save every consumer, delete the redirector only after a COLD editor shows no consumer naming the old path. A half-moved collection can crash the next cold boot.
- **Renamed a C++ module; assets break.** The module name is in every asset's import table (`/Script/<Module>`), invisible to a plain text search of `Content/`. **Fix:** `+PackageRedirects=(OldName="/Script/Old",NewName="/Script/New")` in `[CoreRedirects]`, one per module (including the `…Editor` sibling).
- **Rebuilding a material crashes with `Assertion failed: !IsRooted()`** in `UMaterialEditingLibrary::DeleteMaterialExpression`, every time, on a fresh editor too. A C++ constructor (`ConstructorHelpers::FObjectFinder`) loads an asset that uses the material at startup, into objects GC never frees, and the expressions come along pinned. **Fix:** C++ defaults naming game assets are `TSoftObjectPtr` loaded where used, never constructor-loaded hard pointers.
- **An offline package parser walks off into garbage on 5.8 packages.** From `EUnrealEngineObjectUE5Version::PACKAGE_SAVED_HASH` (1016) the summary writes an `FIoHash` + `TotalHeaderSize` BEFORE the custom versions (`CoreUObject/Private/UObject/PackageFileSummary.cpp:176/236/254`); an older parser reads the hash's first 4 bytes as the custom-version count. **Fix:** branch on the file version.
- **A Blueprint's parent read from the import table is wrong.** The import table lists casts and parents alike. **Fix:** read the asset-registry tag `NativeParentClass` (offline from the package, or `AssetRegistry` in python).
- **A path the cooker cannot see works in the editor and vanishes in the shipped build.** A `"/Game/…"` string or `ConstructorHelpers` path in shipping C++ is not a cook dependency. **Fix:** reference content through `UPROPERTY` soft/hard pointers, data assets or the Asset Manager; list maps in `MapsToCook`.
- **A redirector deleted after a folder rename leaves a map with a null reference.** `rename_directory` leaves an `ObjectRedirector` per asset; python has no fixup-redirectors API. **Fix:** `get_referencers` for EVERY redirector before deleting it, not a sample; referenced ones stay.
- **A map loaded with a missing dependency loses that reference forever once saved.** The load nulls the reference in memory (a `LoadErrors` line names the missing package); a save writes the null. **Fix:** never save a map after such a line; unload it with `new_blank_map(False)`, repair the asset side (restore the asset or a redirector), then reload. A map already saved that way: `git checkout` it while the editor is closed.

## Blueprint graphs

- **The editor will not close: «save changes?» after a session that only READ blueprints.** Reading a graph with `editor_toolset.toolsets.blueprint.BlueprintTools` (`read_graph_dsl`, `get_node_infos`, sometimes `get_connected_subgraph`) resaves the Blueprint or leaves it dirty; `compile_blueprint` saves. **Fix:** list dirty packages before every `CloseMainWindow`, read-only sessions included; save what reading dirtied, then after the editor exits restore files you did not mean to change with `git checkout`.
- **Editing Blueprint graphs.** Through `call_tool` with toolset `editor_toolset.toolsets.blueprint.BlueprintTools` (`find_nodes`, `get_connected_subgraph`, `create_node`, `connect_pins`, `break_pins`, `set_pin_value`, `compile_blueprint`). `find_node_types` needs `context_pins: []`. A self node cannot be created by type id — reuse an existing `K2Node_Self`. The engine's own Agent Skill `BlueprintBasicsSkill` (`AgentSkillToolset.GetSkills`) has the reading/writing order for its graph DSL.
- **`read_graph_dsl` prints nodes as `ToolMenus|Get`, and a variable looks unused.** Unresolved nodes are printed by menu path, and a combined get+branch node of a boolean variable is one of them: the DSL shows only its setters, so the variable seems written and never read. Never conclude «unused» from the DSL alone; use `get_connected_subgraph` / `get_node_infos` for the real node types, and never feed a whole graph's DSL back to `write_graph_dsl`. A very large graph (a character's EventGraph) may not read at all (`UserRaisedError in BlueprintTools.read_graph_dsl`): walk it from `find_nodes` instead.

## Python in the editor and in PIE

- **A `/Game/...` path passed as an argument from Git Bash arrives as `C:/Program Files/Git/Game/...`** (the log says the asset «is not valid»; the MCP tool returns an empty body). MSYS rewrites POSIX-looking argv. **Fix:** prefix the command with `MSYS_NO_PATHCONV=1`, or keep the paths inside the python sent on stdin.
- **An actor turned by `unreal.Rotator(0, 90, 0)` faces the wrong way.** The positional order of the python `Rotator` is roll, pitch, yaw — not C++ `FRotator(Pitch, Yaw, Roll)`. **Fix:** always keywords: `unreal.Rotator(roll=0, pitch=0, yaw=90)`.
- **A combo or another time window never triggers from a script.** A background editor throttles to ~3 fps, so short input windows slip between frames. **Fix:** start the editor with `"-ini:EditorSettings:[/Script/UnrealEd.EditorPerformanceSettings]:bThrottleCPUWhenNotForeground=False"` for time-dependent checks; per-frame input goes through `unreal.register_slate_post_tick_callback`.
- **`get_subsystem` is missing on the GameInstance; `SubsystemBlueprintLibrary` is not exported.** **Fix:** `unreal.ObjectIterator(unreal.SomeSubsystem)` and take the first object whose name has no `Default__`.
- **`load_blueprint_class` returns None during PIE.** **Fix:** `unreal.load_class(None, '/Game/Path/BP_X.BP_X_C')`; an ability then starts with `asc.try_activate_ability_by_class(cls, True)`; gameplay events go through `unreal.AbilitySystemLibrary.send_gameplay_event_to_actor`.
- **Python globals are gone on the next call.** Every call runs in a fresh scope (verified with Remote Execution). **Fix:** keep state across calls (a per-frame callback's results, a handle to unregister) as attributes of the `unreal` module and read it from the next call.
- **`inject_input_for_action` does nothing.** An `InputActionValue` cannot be filled from python (`import_text` silently leaves 0/Boolean). **Fix:** `inject_input_vector_for_action(ia, unreal.Vector(x, y, 0), [], [])` on the `EnhancedInputLocalPlayerSubsystem` (found through `ObjectIterator`); it reaches widget events and works on pause. An `InputAction` read while the game is paused needs `bTriggerWhenPaused = true`.
- **Two equal `GameplayTag`s compare unequal.** `==` is not implemented for tags in python. **Fix:** compare `export_text()`; build a tag with `t = unreal.GameplayTag(); t.import_text('(TagName="A.B")')`.
- **A screenshot has no game UI.** `HighResShot` captures the scene only. **Fix:** the console command `shot showui`.
- **A short reaction is never seen by a polling check.** A state that lasts a frame ends between two calls (seconds apart). **Fix:** measure by timestamps in the log, or in C++ automation subscribe with `RegisterGameplayTagEvent` instead of polling.
- **`CloseMainWindow()` right after `editor_request_end_play()` returns true and nothing happens.** The request arrives while the editor is still tearing PIE down and is lost; the log keeps writing ordinary lines and the MCP server answers — it is not a modal. **Fix:** wait a few seconds after stopping PIE; if `WaitForExit` times out while the server answers and the log grows, call `CloseMainWindow()` again instead of waiting longer or killing.

## Materials

- **Grey checker (the Default Material) on instanced/foliage/skinned meshes — only in a packaged build.** A material must declare usage for its geometry or the renderer substitutes the default material. The editor sets a missing flag at load and recompiles, so the preview, thumbnails and property read-back all look right; the cook says nothing. Flags: `MATUSAGE_InstancedStaticMeshes` for ISM/HISM **and foliage — there is no foliage usage in 5.8** (`EMaterialUsage`, `Engine/Public/Materials/MaterialInterface.h:76`), `MATUSAGE_SkeletalMesh` for every slot a skinned mesh draws, `MorphTargets`, `SplineMesh`, `Niagara*`, … **Fix:** set the flags on the master (`bUsedWithInstancedStaticMeshes`, `bUsedWithSkeletalMesh`, … then save) and test on a packaged build or a cooked instance. Flags are one-way: nothing clears one; delete and rebuild the asset when a flag must go.
- **A skeletal mesh slot draws the default material in game only.** Same cause, for the drawn slots of a skinned mesh. Imported meshes routinely carry slot entries no LOD section draws — those render nothing and need nothing; judge the slots the built LOD sections point at. The same sections decide the empty-slot case on any mesh, static or skinned: every slot a built LOD section draws through must carry a material, and an empty one draws the Default Material in game. A mesh with no built render data cannot say which slots are drawn — report it as «cannot tell», never as a pass.
- **Glass looks like a flat tinted film, no highlights.** `TranslucencyLightingMode` defaults to `TLM_VolumetricNonDirectional` (`Engine/Classes/Engine/EngineTypes.h:322`), built for smoke: it ignores the normal and gives no specular. **Fix:** pick the mode for the surface:

  | Mode | When |
  | --- | --- |
  | `TLM_VolumetricNonDirectional` (default) | smoke, dust, particles — cheapest, normal ignored |
  | `TLM_VolumetricDirectional` | same, normal taken into account |
  | `TLM_VolumetricPerVertexNonDirectional` / `…PerVertexDirectional` | lit per vertex — much cheaper pixel shader |
  | `TLM_Surface` | glass/water on a budget: blurry, limited range, **diffuse only** |
  | `TLM_SurfacePerPixelLighting` («Surface ForwardShading») | glass/water done properly — specular from local lights, **most expensive** |

  Forward translucency takes no SSR: in a level without a reflection capture glass looks dead; judge it on a built map.
- **A mesh goes white in game, the editor shows it fine.** `LogMaterial: … Failed to compile Material for platform …, Default Material will be used in game. (Node TextureSampleParameter2D) Sampler type is Color, should be Linear Color for …` — a texture's `SRGB` was flipped without its sampler node's `SamplerType`; the editor keeps drawing the previously compiled shader. **Fix:** change both in one pass (masks/ORM `LinearColor`, albedo `Color`, normals `Normal`), `MaterialTools.recompile` (raises on failure), and read the PIE log before touching the asset.
- **A scripted material rebuild «did not take».** An open Material Editor tab in the GUI overwrites the rebuilt graph when it saves. **Fix:** close the tab, or rebuild in an editor with no such tab open.
- **A Custom node post-process effect needs neighbour taps (blur, offset copy) and looks graph-only.** It is not: HLSL in a Custom node can call `SceneTextureLookup(UV, <id>, bFiltered)` (`Engine/Shaders/Private/MaterialTemplate.ush:3237`) with `GetDefaultSceneTextureUV(Parameters, <id>)` (`:1324`) for the start UV; `14` is `PPI_PostProcessInput0` (`Engine/Public/MaterialSceneTextureId.h`). The material needs at least one SceneTexture expression so the lookup is compiled in.
- **A post-process material comparing scene colour against `CustomStencil` / GBuffer crawls and misaligns under TSR.** At the default `BlendableLocation` (after tonemapping) the frame is at DISPLAY resolution while `CustomStencil` stays at RENDER resolution and is never temporally resolved — `GetDefaultSceneTextureUV` extent-corrects only `PostProcessInput0..6`. **Fix:** run it `BeforeDOF` (both on one grid, TSR anti-aliases the result). Price: before the tonemapper the frame is HDR — a «nearly black» 0.02 survives as grey, bright needs values well above 1.
- **A Custom node input fails with `use of undeclared identifier`.** Input names are HLSL identifiers: a Material Parameter Collection parameter with spaces (`Base Wetness`) cannot be an input name as is — name the input differently and bind the parameter by its real name.
- **A per-place look cannot be set on a Material Instance.** A `MaterialParameterCollection` is the one input an MI cannot override (it is world-wide by design); per-place values go on instances or post-process volumes. A material cannot read a settings object either: a subsystem writing the collection is the bridge from Project Settings.
- **A wired `Refraction` pin does nothing, or bends the image the wrong way.** The material's `RefractionMethod` decides how the pin is read, and it defaults to `RM_None` (`UMaterial` constructor, `Engine/Private/Materials/Material.cpp`), which ignores the pin. `RM_IndexOfRefraction` reads a float index of refraction; `RM_2DOffset` reads a float2 screen offset, independent of resolution and aspect (`ERefractionMode`, `Engine/Classes/Engine/EngineTypes.h:362`); `RM_PixelNormalOffset` scales a normal-based offset (1.0 = none). **Fix:** set the method to match what the pin carries — float → index of refraction, float2 → 2D offset — on a translucent material.
- **Material time stands still in the viewport.** It only runs with the viewport in Realtime; a slow sky drift is invisible there anyway.
- **A pack's `_Metallic` map with an alpha.** RGB is metallic, alpha a gloss term — which one is in the pack material's graph: an alpha wired straight to Roughness (no OneMinus, `MaterialTools.get_expressions`) IS roughness; inverting it paints everything wet. Read the graph before repacking (ORM convention: R=AO, G=roughness, B=metallic).

## Meshes and skeletal

- **`import_file` refuses a `.glb`.** `StaticMeshTools.import_file` takes fbx/obj only: convert first. (And it does not save — see Saving.)
- **A doorway is solid; a prop collides as one blob.** Without simple collision the engine wraps the mesh in one convex hull. **Fix:** ship `UCX_<Mesh>_NN` boxes in the FBX. `SOCKET_<Name>` empties export as static-mesh sockets.
- **Topology looked fine in the DCC, cannot be judged after import.** UE triangulates on import; judge quads before.
- **Morph targets missing on a Nanite skeletal mesh.** Nanite skeletal has no morphs: keep such meshes non-Nanite.
- **A property named `skeletalMesh` does nothing in 5.8.** The mesh property is `skeletalMeshAsset`; a placed actor's component is `SkeletalMeshComponent0`. `get_bone_names` / `get_material_slots` take the mesh as `{refPath}`.
- **Skeletal thumbnails look broken/dark.** They are badly lit: judge in a lit level with `CaptureViewport`.
- **FBX export of a skeletal mesh dies in a commandlet** with `Assertion failed: MeshObject` (`SkinnedMeshComponent.cpp:4987`). The exporter reads vertices through `GetCPUSkinnedVertices`, which needs a registered component's render state; a commandlet has no world. **Fix:** run the export in a full (headless) editor: `UnrealEditor-Cmd <project> -unattended -nopause -nosplash -RenderOffScreen -ExecCmds="py <file>, quit"`. Texture export is fine headless: `-run=pythonscript` + `unreal.TextureExporterPNG`.
- **`-run=pythonscript -script=<path>` exits in seconds, no `LogPython`, no traceback.** The value is not parsed as a quoted path; a path with a space is truncated (`-abslog=` too). **Fix:** run scripts from a space-free path.
- **A skeletal import onto an existing skeleton renamed its root bone** (`root_001`, or the armature's name) — for every mesh on it. The top FBX node is read as the root bone and Blender exports the armature object as a node. **Fix:** name the armature object exactly as the target root (`root`), build no bone of that name; read the bone list back on another mesh of the skeleton.
- **A character from Blender vanishes on some clips (idle) while walk/jump play.** The unit conversion lands as scale 100 on the armature = root bone; bones whose translation the clip carries as-is (IK bones in `Animation` mode) go 100× too far. **Fix:** check `unreal.SkeletonModifier.get_bone_transform("root", False)` scale is 1; export in centimetres (scene unit 0.01).
- **A skeleton fitted only by joint positions explodes on the first clip.** Clips store rotations in each bone's local axes; bones rebuilt from head/tail points get frames ~90° off, invisible at rest. Rest pose also hides a skeleton offset a metre from its mesh. **Fix:** take bone frames from the target skeleton; check joints lie inside the geometry they drive.
- **Programmatic skeletal edits.** One `FScopedSkeletalMeshPostEditChange` per operation (each `PostEditChange` rebuilds all LODs); never let a write-back recompute normals/tangents (`BuildSettings.bRecomputeNormals=false`, or authored normals vanish on the next DDC rebuild); never reorder/weld/renumber vertices (morph deltas and skin weights are index-keyed; adding vertex instances is safe); reuse live `UMorphTarget` objects (new ones over live ones crash async DDC); material bakes need a real RHI (die under `-nullrhi`).
- **Skin weights contaminated on every rig at once.** `GetVertexBoneWeights` does `SetNum(Num)` then `Add`s (`MeshBoneWeightFunctions.cpp:293-299`): a hoisted array keeps the previous vertex's weights. **Fix:** `Reset()` before every call.
- **GeometryScript silent corruption** (compiles, returns success, wrong geometry): `ApplyMeshOffset` smooths at its defaults (set `SolveSteps=0, SmoothAlpha=0` for a pure offset); `RemoveSmallComponents(MinVolume=0)` can delete an open shell (negative volume — use `Lowest()`); vertex IDs are sparse (`GetNumVertexIDs` + `IsValidVertexID`); `TransferBoneWeightsFromMesh` has no outcome pin, reversed args compile, and it crashes on a non-compact target (`Containers/Map.h.inl:651` — `CompactMesh` first); `PruneBoneWeights` prunes by bone, not weight; `ApplyMeshMorphology` re-meshes and destroys UVs; `ComputeSmoothBoneWeights` takes the `USkeleton`'s pose, not the mesh's (`MeshBoneWeightFunctions.cpp:640`) and weights every bone, IK and correctives included.
- **HISM instances set as a property are gone after reload.** `PerInstanceSMData` is `SkipSerialization`. **Fix:** `AddInstance(s)`, then `BuildTreeIfOutdated`; for any `SkipSerialization` property the evidence is a reload.
- **Landscape Grass Type output cannot be verified headless.** Grass instances are generated per view at runtime; no package or query holds them.

## Animation and retargeting

- **Retargeted feet are nailed in place under a foot-placement graph (GASP-style).** The IK bones stayed in reference pose. **Fix:** the retargeter's Pin Bones op with Epic's pairs: `ik_foot_l/r ← foot_l/r`, `ik_hand_gun` and `ik_hand_r ← hand_r`, `ik_hand_l ← hand_l`, the ik roots ← `root`.
- **A shared skeleton deforms bodies of other proportions badly.** Translation retargeting per bone, Epic's recipe: `Skeleton` everywhere, `AnimationScaled` on `pelvis`, `Animation` on `root` and `ik_*`.
- **Retargeted clips have no twist motion on the Manny skeleton.** Manny's twist/corrective bones are driven by its post-process Anim Blueprint, not by clips. Keep the post-process ABP on the mesh.
- **Retarget output changed after an engine upgrade.** It does: rebuild retargeted clips from the source, do not patch old outputs.
- **Retarget once, offline.** A runtime copy-pose (invisible donor mesh driving the visible one) exists only to work around a foreign skeleton; bake the retarget instead.
- **A sound AnimBP architecture (from Epic's Game Animation Sample):** Motion Matching via a chooser table → Pose Search databases, BlendStack, steering/orientation warping, foot placement; linked anim layers per MECHANIC behind layer interfaces, relinked by a component; thread-safe pose functions with a call counter (0 proves a layer is not wired); montages + Motion Warping for actions that must land at a world point; one Pose Search database per coherent capture, never mixed packs.

## Niagara

- **`SetVariable` / `AddUserVariables` / `SetEmitterData` / `SetSystemData` succeeded and nothing changed.** They succeed silently on a type/name mismatch. **Fix:** read every value back.
- **A bool parameter reads «wrong».** `FNiagaraBool` is True = −1, False = 0.
- **A GPU emitter vanishes off-camera, or shows «0 particles» only in a cooked build.** GPU emitters need fixed bounds. Default gameplay FX to CPU unless the count needs GPU.
- **`SetStackInputData` cannot reach an input.** Inputs hidden by a static switch are unreachable; a `NiagaraExt_StackInputData_HlslExpression` on the module input can bind `User.*` by name (no spaces in those names). Read `GetDynamicInputChain` before replacing a dynamic input and relink the operand (`inputNameStack: ["Input", "B"]`).
- **Cross-emitter or game↔FX events do not fire on GPU.** Niagara events are CPU-only: use Niagara Data Channels.
- **`CaptureAssetImage` shows nothing for a Niagara system.** It does not render Niagara; look in a level.
- **There is no from-scratch system authoring through the toolsets.** A new system is a copy of an existing one plus stack edits.
- **A depth/normal-based outline skips the particles.** Translucent sprites write no depth/normal.
- **The Parameter Collection path is baked into compiled data** — see Packages.
- Reusable formulas worth making once as scratch-pad modules:

  | Piece | Formula |
  | --- | --- |
  | rest-position drift (hovering dust) | `Position = RestPos + (Noise3(RestPos·U/h + t·speed) − 0.5)·D·h` — set, not integrated |
  | wrap wind + fade band | `pos = min + frac((pos − min)/size)·size`; alpha × `sat(u/f)` at the wrap faces, `f = rand(0, 0.499·|speed|)` |
  | square-random size | `size = mean × RandRange(a, b)²` |
  | shimmer | `lerp(1, sat((n − c')/(1 − 2c')), S)`, `c' = 0.49·Contrast` → rgb and alpha |

  | blackbody fire | colour = `BlackBody(lerp(800, 3500, T))`, emissive = `sat((T − 0.05)/0.95)·k` |
  | inverse-sphere attractor | attraction × `step(R, dist)` |

## Levels and actors

- **Actor edits switch the map in the GUI editor.** Editing actors of a level through the subsystems makes it the current level. Do level authoring in an editor nobody is looking at, or tell them.
- **A `StaticMeshActor` spawned or moved in-session, or a component property edited on the CURRENT level, is not drawn in a capture.** Its render state is not recreated. **Fix:** load another map and back (reloading the same path is a no-op) before shooting; `SceneTools.remove_from_scene` takes effect live.
- **Reads and captures right after a script authored a map return zero bounds and empty shots.** Toolset reads and captures answer for the current world (often `Untitled`), not for the map the script wrote. **Fix:** `SceneTools.load_level` the target map before any read or capture (`epic-mcp-toolsets.md` §Describe current state).
- **A second run of a map-editing script doubles its actors, or one window's run loses another's placements.** A map is one file: a script that adds to a shared map stacks on what an earlier run left, and two sessions on one map overwrite each other on save. **Fix:** make the script re-runnable — it loads the map from disk at its start, labels everything it adds with one prefix, and removes that prefix first. Build each room or test setup in a map of its own; a shared map is edited by one session at a time.
- **`set_properties` on `BodyInstance` answers true and changes nothing.** A collision-free `StaticMeshActor` needs `StaticMeshComponent.bUseDefaultCollision=false` together with `BodyInstance` `(CollisionEnabled=NoCollision,CollisionProfileName="NoCollision")` — with the default `true` the mesh's own collision wins (a sky dome around a `PlayerStart` pushes the pawn out through its wall). Set it in python on the component (`set_collision_enabled`, `set_collision_profile_name`) or in the Blueprint.
- **Post-process blendables cannot be added with `set_properties`.** The setter refuses to grow `Settings.WeightedBlendables`; add them in python (`FWeightedBlendables`) or in the Blueprint; one blendable per volume keeps it readable.
- **`Component.Property` paths cannot create `EditInlineNew` / instanced objects or reach nested SCS components.** Bake them into a Blueprint subclass.
- **A Blueprint's mesh scale/rotation is ignored by the placed actor.** The ROOT component's transform is the actor's and placement overwrites it. **Fix:** an empty `USceneComponent` root with the mesh under it.
- **A placed actor does not follow later changes to its Blueprint's components / CDO** — see SKILL.md "A placed instance does not follow its asset"; re-place it. A copied actor takes the configured INSTANCE's properties, not the Blueprint defaults.
- **After a C++ change to a component's attachment/default transform the Blueprint reads a third value.** A Blueprint that ever touched the transform serialized an override that outranks the CDO; re-parenting in C++ does not clear it. `reset_properties` resets to the TYPE default (zero), not the archetype. **Fix:** read `/Game/…/BP_X.Default__BP_X_C.<Component>` after the C++ change and set the intended numbers explicitly.
- **Components built in `OnConstruction` double on Play.** PIE duplication carries the components but not a `Transient` bookkeeping list, so the rebuild lays a second set. **Fix:** tag built components (`ComponentTags`) and clear by tag.
- **Reparenting a vendor Blueprint to `AActor` scatters its pieces.** Its scene components were inherited from the pack's parent; the orphans are re-nested with old relative transforms. Reparenting onto your C++ class renames the pack's colliding variables (`ValidateVariableNames … changed to X_0` in the log). **Fix:** keep the parent surface minimal with unlikely names; read the log after `set_parent`.
- **An NPC turns to its target but does not move** (at most `LogCrowdFollowing: Unable to find RecastNavMesh instance`). `RecastNavMesh` defaults to Static generation, so PIE copies the editor's navmesh; the editor spawns `RecastNavMesh-Default` on load but lifts its `AsyncLoadLock` without a rebuild (`NavigationSystem.cpp:5997`), so a map with a `NavMeshBoundsVolume` and no SAVED tiles is empty in play. **Fix:** build paths and save the map; prove with a path query between the two actors.
- **A ~90 cm passage passes or blocks the navmesh depending on where it stands.** After the agent radius is eroded from both sides about one cell is left; grid alignment decides. Make passages comfortably wider than `2 × AgentRadius + CellSize`.
- **The editor dies ~90 ms after PIE starts** with `Assertion failed: ColorRT [RHIResources.h:5395]` under `FViewport::GetRawHitProxyData`. During PIE `GEditor->GetActiveViewport()` is the game viewport, which has no hit-proxy target. **Fix (C++ editor code):** bail when the viewport equals `GEditor->GetPIEViewport()`.

## UMG, Slate, CommonUI

- **A brush with a real texture paints flat colour.** `FSlateBrush::ImageType` defaults to `NoImage` and is not derived from the resource. **Fix:** set `ImageType = FullColor` on every brush written by script.
- **A Box (nine-slice) brush draws nothing while it reads as assigned.** Margins are fractions per axis: top + bottom ≥ 1 leaves a negative centre. They also resolve to pixels against the widget's own size (12 px corners do not fit a 9 px bar).
- **Engine widget defaults eat the art.** `UProgressBar::FillColorAndOpacity` defaults to blue `(0, 0.5, 1)` and multiplies the fill brush; `USlider` draws its fill over the track (an opaque track hides it); a widget with no content collapses to zero size. **Fix:** explicit sizes, every multiplying default set, judge by a capture, not by property read-back.
- **A CommonUI button style made in this session renders the engine's grey button.** A `UCommonButtonStyle` created in the same editor session is not picked up until the editor restarts.
- **Clicks go to decorations.** Non-interactive elements should be `HitTestInvisible` / `SelfHitTestInvisible`.
- **«A required widget binding X was not found».** A child's name must equal the C++ `BindWidget` field exactly (the toolset's `widgetDisplayName`). The same warning during `FKismetEditorUtilities::CreateBlueprint` on an empty tree is a decoy.
- **A Widget Blueprint built from C++ keeps ghosts / ensures on compile.** The compiler collects source widgets by OUTER (`UBaseWidgetBlueprint::ForEachSourceWidget`), not from `RootWidget`: to rebuild, `Rename` old widgets into the transient package. `WidgetVariableNameToGuidMap` must match the named-widget set both ways (`WidgetBlueprintCompiler.cpp:781` «was added but did not get a GUID», `:815` «was deleted but still has a GUID»); keep it with `OnVariableAdded` / `OnVariableRemoved`.
- **CommonUI never returns input after a screen closes.** The action router exists only with a `UCommonGameViewportClient`-derived viewport client; the log says `Using CommonUI without a CommonGameViewportClient derived game viewport client` at every world start. **Fix:** `[/Script/Engine.Engine] GameViewportClientClassName=/Script/CommonUI.CommonGameViewportClient`.
- **The second menu does not free the mouse.** `UCommonUIActionRouterBase` applies an input config only when it differs from the current one; a screen that hands input back with `SetInputMode(GameOnly)` leaves the router at «Menu». **Fix:** hand input back through `SetActiveUIInputConfig(FUIInputConfig(ECommonInputMode::Game, …))`.
- **A CommonUI action (Back) is dead on one gamepad key.** CommonUI finds an action's keys in `EnhancedActionMappings`; `RebuildControlMappings` leaves out a lower-priority context's mapping of a key a higher-priority context gives to a `bConsumeInput` action (`EnhancedInputSubsystemInterface.cpp`, the `AppliedKeys` check). **Fix:** UI mapping context above every game context, none of its actions consuming input.
- **Editor class icons.** Register monochrome SVGs as `FSlateVectorImageBrush` in the module's `FSlateStyleSet` under `ClassIcon.<Class>` / `ClassThumbnail.<Class>` so `FClassIconFinder` finds them.

## Audio

- **Volume options fight a Sound Mix, or a mix applies values nobody set.** Adjusters baked into a `USoundMix` asset apply on every push, on top of whatever the game sets. **Fix:** keep Sound Class / Sound Mix assets as the hierarchy only (class parents and children, a bare mix) and push the adjusters at runtime — `UGameplayStatics::SetSoundMixClassOverride` then `PushSoundMixModifier` (`Kismet/GameplayStatics.h`), with the values coming from settings or the save.
